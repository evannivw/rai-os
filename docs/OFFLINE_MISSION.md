## Actual result and command

```sh
. "$HOME/.cargo/env"
# Explicit oracle-supplied replay, no credential/network; real host publication.
python3 -B scripts/offline_mission.py --source replay --output target/offline-replay-new
# One real Meta call; use your own ignored .env.local per META_BRIDGE.md.
python3 -B scripts/offline_mission.py --source meta --output target/offline-live-new
```

The output directory must be new; --debug selects a debug host build. Only the
host Rust binary is built. No QEMU or kernel binary is required for this increment.
The legacy positional kernel argument is passed as host-only and is unused by
these explicit CLI modes. This is documented compatibility, not guest execution.

On successful verification, open `run/package/published/index.html` directly from
the output folder. The reader contains exact document text, local document links,
quoted evidence, open tasks, manifest and the recorded plan. It has no JavaScript,
remote fonts, downloads, forms, external images or network resources. Copy the
whole published directory, or unpack `run/aurora-offline.zip` on another computer.
The ZIP's member names and exact bytes are compared to the verified directory.

The independent checker can be rerun without a model call:

```sh
python3 -B scripts/check_offline_pack.py target/offline-live-new/run/package/published
```

The integrated browser blocked file:// navigation under its security policy, so
visual/browser-disconnected verification could not be performed. No alternate
browser or local server was used to bypass the restriction. Reader structure,
source text, internal/file links, restrictive CSP and absence of external resources
were verified programmatically; manual browser review remains pending.

## Ownership and verification boundary

mission.rs owns a strict typed plan and compiled public content. mission_runner.rs
owns host I/O, escaped HTML rendering and candidate publication. Provider code uses
an explicit separate schema; old semantic/batch prompts and settings are unchanged.
The Python harness handles logs/ZIP transport; the independent Python checker owns
the fixed-case acceptance rules. No new Rust dependency, unsafe code or kernel/UI
implementation was added. The HTML reader is a host artifact, not a native guest UI.

The provider receives only the goal, policy and thirteen authorized document
contents. Expected answers, denied content, local paths and credentials are not
sent. This fixed corpus is compiled into the host; arbitrary file discovery,
PDF extraction, desktop indexing and runtime catalog updates are NOT implemented.
Version identifiers bind request text/version, catalog version and permission
version. This is a static fixture permission model, not production access control
or runtime revocation.

The model can publish a selection, clarify or report blocked; it cannot supply
paths, execute code, grant access, change source bytes or send messages. Limits:
2048 output tokens for this new mode only, 8192-byte plan, up to ten documents,
2–6 evidence quotes and 0–4 pending-action quotes, each at most 300 bytes; reason
1–240 bytes. Meta uses muse-spark-1.3 with minimal reasoning and strict
rai_offline_mission schema. One call, no retry/fallback. Existing provider timeout,
response limit and redacted diagnostics apply. Diagnostics and mission_response
summarize the same call and must not double-count usage.

Rust admission checks shape, identity, permitted IDs, duplicates and literal quote
existence. It does NOT establish that a plan satisfies arbitrary intent. A permitted
but incorrect draft/interface may reach an unpublished candidate, then be rejected
by the separate fixed-case oracle. The oracle requires exact expected membership,
release/dependency evidence and pending actions; verifies source bytes and SHA-256
against the independent fixture catalog; and inspects the reader and file manifest.
The fixture hashes bind the authored corpus; they are not owner signatures.

Publication requires a new output directory. The Rust builder writes candidate/,
invokes the fixed independent checker, and renames the directory to published/
only after success. On failure the candidate may remain inspectable but published/
is absent. An existing output directory is rejected before writes, so an earlier
package is not silently overwritten. This is a checked one-shot publication, NOT
an automatic updater or persistent semantic service. Incremental regeneration,
change detection and retaining a guest publication for this new corpus remain
future work. The local host/checker is trusted; this is not protection against a
malicious host editing files after checking.
