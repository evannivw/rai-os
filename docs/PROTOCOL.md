# UART protocol v1

A small bounded line format, without JSON or heap-allocated framing buffers. This is
request transport, not IPC between isolated processes. UART0 has one host
reader/writer. There is no authentication, negotiation, concurrency, or ID deduplication.

## Format

Examples use literal escape notation for actual TAB, LF, and CR bytes:

```text
@rai1\t1\thelp\n
@rai1\t2\tinfo\n
@rai1\t3\techo\thello from host\n
@rai1\t3\tok\thello from host\r\n
@rai1\t4\terr\tunknown_operation\r\n
```

Grammar: @rai1 TAB id TAB operation [TAB argument] line-ending.
help/info/uptime/memory.info/memory.check/mmu.info/context.check/timer.check/schedule.check/user.run/user.spin require exactly three fields; echo requires four, with a possibly
empty argument. Names are case-sensitive. ID: 1-10 ASCII digits with value
1..4294967295; leading zeros are allowed and preserved. IDs are not remembered.

- Maximum request: 256 bytes excluding terminator; no truncation.
- Input: printable ASCII; TAB separates machine fields only.
- Echo arguments cannot contain TAB, CR, LF, NUL, escapes, or Unicode.
- Input terminators: LF, CR, or CRLF (one terminator). Replies always use CRLF.
- Lines beginning with @ are machine requests and are not echoed.
- Other lines are human commands: help, info, uptime, echo, echo <text>. Human input is
  echoed; Backspace/Delete edit it. There is no guest prompt, keeping machine
  replies at the beginning of a line. Empty human lines do nothing; spaces are
  not normalized.
- Wait for Console ready before sending. One request followed by its response
  is sufficient for this milestone.

## Uptime payload

Request: `@rai1\t5\tuptime\n`. Response payload:
`uptime_ms=<unsigned decimal>; counter_hz=<positive unsigned decimal>`.
The surrounding response remains `@rai1 TAB id TAB ok TAB payload CRLF`.
No argument is accepted, including an empty fourth field. The first field is
elapsed guest counter time since early kernel clock initialization, rounded down
to milliseconds. The second is the system counter frequency, not CPU frequency.
Values are generated by the guest; no host timestamp is substituted. See
[CLOCK.md](CLOCK.md) for assumptions and limitations. This is an additive v1
operation; older kernels respond with unknown_operation.

## Cooperative task operations

`task.start`, `task.status`, and `task.cancel` provide one bounded word-count
job. See [TASKS.md](TASKS.md) for exact arguments, lifecycle, payload, errors,
and educational pacing. Task IDs are distinct from request IDs.

## Physical memory diagnostics

`memory.info` and `memory.check` each accept exactly three fields (no argument).
Both are also available as argument-free shell commands. `memory.info` returns:

```text
page_size=4096; total_pages=256; free_pages=250; used_pages=6; pool_start=0x<16 lowercase hex digits>; pool_end=0x<16 lowercase hex digits>
```

Counts describe only the reserved pool. Addresses come from the linked image,
not request arguments. `memory.check` reserves/tests/releases its currently free pages and on
success returns `checked_pages=250; exhausted=true; zeroed=true; reused=true; free_pages=250`.
The MMU permanently owns six pages. If no pages are free, the diagnostic returns
`memory_busy` before starting; failed
internal invariants halt rather than fabricate success. See [MEMORY.md](MEMORY.md)
for blocking behavior and unsafe contracts. There is no arbitrary memory API.
These additive v1 operations return unknown_operation on older kernels.

## MMU status

`mmu.info` accepts exactly three fields and is also an argument-free shell command.
Its payload is:

```text
enabled=true; mode=identity; granule=4096; table_pages=6; root=0x<16 lowercase hex digits>; tcr=0x0000000080993019; mair=0x0000000000004400; wxn=true; caches=false
```

Enabled/WXN/cache flags, root, TCR and MAIR are read from EL1 registers. Mode,
granule and table count describe the fixed mapping policy. This is read-only
status, not a remapping API. See [MMU.md](MMU.md). Older kernels return
unknown_operation for this additive v1 operation.

## Context diagnostic

`context.check` accepts exactly three fields and is also an argument-free shell
command. It performs two bounded EL1 SVC/ERET probes, then returns:

```text
round_trips=2; registers=31; flags=true; stack=true; resumed=true
```

These flags reflect observed register/flag/stack comparisons, not a cached boot
status. A mismatch returns `context_corrupt`; a fatal fault halts with the usual
diagnostic and no success reply. There are no user-supplied context addresses or
register values. See [CONTEXT.md](CONTEXT.md) for safety and scope. Older kernels
return unknown_operation for this additive v1 operation.

## Built-in user program

`user.run` has no argument (exactly three machine fields, or the shell command).
It synchronously runs the linked EL0 program; it does not accept source, binary
paths or raw addresses. Normal payload:

```text
mode=EL0; state=exited; code=0; syscalls=2; rejected=0; output=Hello from EL0
```

A contained program fault returns a report with `mode=EL0; state=faulted`, followed
by `esr`, `pc`, `far_raw`, `spsr`, `sp` (each 0x plus 16 lowercase hex digits) and
`syscalls`. An outer `ok` means the run request was handled, not that the program
succeeded. Check state and exit code. Reentrant invocation returns `user_busy`;
normal single-request UART use cannot trigger it. All invocations now share a
fixed 100 ms guest-counter deadline; expiry produces `state=timed_out`. Only
linked programs are accepted, with no scheduler or arbitrary loader. See [USER_PROGRAM.md](USER_PROGRAM.md).

## Errors

bad_version, bad_id, bad_frame, bad_args, unknown_operation, invalid_byte,
line_too_long, uart_error. Parsing errors retain a valid ID; invalid IDs and
transport errors use 0. Validation order: version, ID, operation/arguments.
Only a fully validated operation can execute.

Invalid bytes, UART errors, and overflow poison the entire line until its next
terminator. The rejected tail never becomes another command. The guest uses a
fixed buffer and has no line timeout. An incomplete request waits for a terminator;
the host must impose its own timeout and terminate the line or restart QEMU.

## Future Meta bridge

The host console currently starts scripts/qemu.sh and uses its stdin/stdout.
Meta calls are not implemented. The key will live in the host environment.
The bridge must validate an allowed operation, field contents, and lengths before
serializing. Never concatenate arbitrary model output onto UART: a newline
starts another request. The guest repeats validation before execution.
The task operations only modify one bounded in-memory job; there is no file access or
arbitrary code execution.

This interface is not a security boundary against a malicious host. Before
adding side effects, define permissions, policy, exclusive protocol mode, and
subsequently real service isolation.

## Controlled timer diagnostic

`timer.check` requires exactly three machine fields, or an argument-free shell
command. A successful reply has this field order (`elapsed_ms` varies):

```text
irq=30; ticks=6; rounds=2; registers=31; flags=true; stack=true; irq_masked=true; timer_disabled=true; elapsed_ms=<decimal>
```

Counts and true flags are emitted only after all observations pass. Errors are
`timer_requires_masked_irqs`, `timer_busy`, or `timer_check_failed`; malformed
arguments return `bad_args`. Failed IRQ delivery can hang the controlled probe;
the host timeout is not guest recovery. See [TIMER.md](TIMER.md).

## EL0 deadline diagnostic

`user.spin` takes no argument (exactly three structured fields) and selects a
linked one-instruction infinite loop. It never voluntarily returns. Both it and
`user.run` have a fixed 100 ms deadline, including time spent handling syscalls.
Timeout is an observed terminal state, not successful completion of user work:

```text
mode=EL0; state=timed_out; budget_ms=100; elapsed_ms=<decimal>; vector=<8 or 9>; pc=0x<16 hex digits>; spsr=0x<16 hex digits>; sp=0x<16 hex digits>; syscalls=<decimal>
```

Vector 9 means a physical timer IRQ from EL0; 8 means expiry observed on synchronous
entry. `syscalls` counts dispatched calls before expiry; the expired request is
not executed or counted. A timeout report omits buffered output. An outer `ok`
only means a report is available. Normal exit/fault payloads retain their format;
saved user status now has IRQ enabled (0x340 excluding NZCV). Invalid arguments
produce `bad_args`. Internal setup/cleanup errors may return `user_busy`,
`timer_busy`, `invalid_timer_frequency`, `timer_deadline_overflow` or
`timer_cleanup_failed`; those branches were not all fault-injected.
See [USER_TIMEOUT.md](USER_TIMEOUT.md) for timing and cleanup guarantees/limits.

## Bounded context-switching diagnostic

`schedule.check` has no argument (exactly three structured fields). It performs
six 20 ms slices per linked EL0 context, then discards both paused contexts. It
accepts no code, task IDs, duration or saved register input. The result contains:

```text
tasks=2; slice_ms=20; irqs=12; switches=11; trace=ABABABABABAB; a_turns=6; b_turns=6; a_ms=<decimal>; b_ms=<decimal>; progress=<12 comma-separated decimals>; context=true; stacks=true
```

Progress entries match the trace; per-context counters must increase. Flags are
emitted only after all actual frame/stack observations pass. The 100 ms deadline
of user.run/user.spin is unchanged and does not apply to this diagnostic's context
lifetime. Parsing errors return `bad_args`. Runtime errors can include
`schedule_busy`, `schedule_user_fault`, `schedule_timer_early`,
`schedule_context_corrupt`, or the timer's existing setup/cleanup errors. A failed
check returns no success report and stops before resuming rejected state. See
[SCHEDULING.md](SCHEDULING.md) for measured timing, tested failures and limitations.
