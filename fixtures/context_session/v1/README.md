# Constant-goal context fixture

The user objective is byte-identical in assigned.json, conflict.json and
resolved.json. Their request_version correlates with observations/<case>.json
version; it identifies a new observation, not a rewritten goal.

A controlled driver delivers three fictional assignment observations. Dispatch is
the configured authority, maintenance advisory. Revision 2 conflicts; revision 3
resolves it. Source labels are fixture data, not authenticated real-world reports.
Expected answers are independent checker inputs and never model context.

Three known development cases, one pass per policy, maximum three Meta calls,
no retry/fallback or post-result tuning. See docs/CONTEXT_SESSION.md.
